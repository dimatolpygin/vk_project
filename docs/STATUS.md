Заказчик прогнал живой прогон и принял. Нетривиальные решения:
(1) схема — не «прямой i2v или коллаж» из ТЗ, а цепочка из двух моделей: шаблон
хранит два промта, фото-модель собирает по первому кадр, Seedance оживляет его

(2) списание больше одной генерации раскладывается по платному и бесплатному
балансам (`charged_paid_gens`/`charged_free_gens`): 40 генераций в один баланс
могут не поместиться, а возврат обязан отдать ровно то, что снял и куда снял;
(3) видео живёт в своей очереди asynq — цепочка занимает воркер минутами
и не должна держать фото-задачи;
(4) доставка результата переделана дважды. Сначала mp4 уходил документом, но
всплыли два ограничения ВК подряд: `video.save` групповому токену недоступен
вовсе («invalid token type», права тут ни при чём — проверено через
`groups.getTokenPermissions`), а загрузчик документов отбивает POST по HTTP/2
ответом 405 (Go договаривается на HTTP/2 через ALPN; воспроизведено на боевом
сервере, по HTTP/1.1 тот же файл проходит). Итог: mp4-документ ВК показывает
без обложки, и по решению заказчика доставка переведена на кадр-превью
плюс кнопку «Скачать видео», загрузка документа убрана;
(5) тарифы под видео заказчик не досчитал — дефолты выведены из себестоимости
($2.40 Seedance + $0.06 кадр ≈ 197₽) и заведены миграцией: промт 40 генераций,
тариф «1 видео» 690₽ за 40 генераций. Это ровно цена генерации из пакета
«30 фотографий», поэтому арбитража между тарифами нет;
(6) заодно главное меню приведено к схеме п. 1 ТЗ. Кнопка «Мое фото» вернулась
в меню вопреки решению этапа 4 — заказчик подтвердил схему; вход через профиль
остался, кнопка скрывается из админки без релиза. Раскладку я сперва собрал
неверно, прочитав «/» и «|» в таблице ТЗ одинаково, — исправлено миграцией 00037;
(7) первый боевой прогон: кадр 38 секунд, Seedance 216 секунд, итого 4,5 минуты.

## Протокол обновления

**При старте сессии**:
1. Прочитать этот файл.
2. `git tag -l "stage-*"` и сверить с колонкой «Закрывающий тег». Тег без записи в таблице = таблица устарела, обновить.
3. `git log --oneline -10` — что менялось последним.
4. Только после этого приступать к работе.

**При взятии этапа в работу**:
1. Обновить «Текущий этап» и «Активная работа».
2. Статус 🚧 в таблице.
3. Закоммитить отдельно: `chore(status): start stage N`.

**При закрытии этапа**:
1. Убедиться, что все чекбоксы в `ROADMAP.md` отмечены `[x]` и реально проверены.
2. Создать тег: `git tag stage-N-done -m "<описание>"`.
3. В таблице: ✅, «Закрывающий тег», «Последний коммит» (`git rev-parse --short HEAD`), «Дата закрытия».
4. Добавить запись в «Историю закрытий».
5. Указать новый «Текущий этап» и «Следующий шаг».
6. Закоммитить: `chore(status): close stage N`.

**Если этап заблокирован**:
1. Статус ⏸ в таблице.
2. В «Известные блокеры»: что блокирует, кого ждём, что нужно для разблокировки.

## Что НЕ хранится здесь

- Длинные размышления и планы — это `ROADMAP.md` и спецификации в `docs/`.
- TODO внутри текущего этапа — это таск-лист активной сессии.
- История изменений кода — это `git log`.

Этот файл — **только снимок текущего состояния по этапам**. Должен помещаться на один экран.
